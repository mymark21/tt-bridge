# Source provenance — public 1.4.x line

This repository's source tree is the **community-reviewable source for the
public `v1.4.x` line**. It is a curated import of the free core from the private
development tree, not a dump of it.

## v1.4.5 (current release source)

- Baseline: dev commit `bac13ef` on `feat/experience-learning-loop`.
- Forward-ported on top of that baseline: the `v1.0.5`/`v1.0.6` security
  hardening (bearer token, Host/Origin checks, HTTP body and WebSocket caps,
  WebSocket origin requirement, URL scheme blocklist, `detachAll` on stop),
  adapted to the multi-instance daemon architecture.
- The extension is TypeScript/Vite source under `chrome-extension/src/`;
  `chrome-extension/dist/` is generated by `npm run build` and is not tracked.
- Release archives are built by `scripts/build-release.sh`, which delegates
  staging to `chrome-extension/tools/package-release.mjs` and writes to
  `build/`.

Deliberately excluded from this tree:

- Private/paid modules (cloud sync, team sharing, verified site packs,
  relay/remote control, audit/compliance/SSO/RBAC, orchestration,
  record/replay, premium site packs).
- Internal research notes, `references/`, acceptance scripts, local deployment
  helpers, and maintainer-specific paths.

## v1.0.4 (frozen)

The published `v1.0.4` release assets were built from an earlier local snapshot
that is no longer on disk. They remain available under tag `v1.0.4` and are not
rebuilt or replaced.

## v1.0.5 / v1.0.6

`v1.0.6` was the last release of the `v1.0.x` line. Its extension source was
the compiled `dist/background.js` bundle because the original TypeScript source
was not recoverable. TypeScript source returned in `v1.4.5`.

## Release assets

Release artifacts are not tracked in this repository. The last `v1.0.x` assets
remain attached to their GitHub Releases; from `v1.4.5` onward,
`.github/workflows/release.yml` builds `tt-bridge-extension.zip`,
`tt-bridge-cli.zip`, and `SHA256SUMS.txt` from the tagged source and attaches
them to the GitHub Release. `scripts/build-release.sh` produces the same files
under `build/` for local verification; that directory is ignored.

## What this means for contributions

- PRs target this source tree and are validated with
  `scripts/build-release.sh` (outputs in `build/`).
- Do not hand-edit `chrome-extension/dist/` or the release zips; edit
  `chrome-extension/src/` and rebuild.
- A future release keeps the TypeScript build and version/source alignment.
